# Creami Cravings — iOS app spec

Personal iPhone app (iPhone 17, iOS 26+, deployment target iOS 18.0) for Ninja Creami recipes: the user's recipe book (76 recipes, "Creami Cravings" by Eli @FitnessProductFinder) plus a few hundred recipes gathered from the web. SwiftUI only, no third-party packages, no accounts, works offline (network is only used for the optional Open Food Facts lookup).

```
UI: the Recipes tab has a segmented control at the top: **Creami | Other Desserts**. Desserts get the same search, filters and favorites. They add a "Dessert type" and "Verdict" filter group and an evidence card on the detail screen: a verdict badge (Proven = green check, Promising = yellow, Unverified = gray), the rating with its count, a summary, and the common fixes as a bullet list. ### Resources/protein_powders.json: the "what protein powder am I using" picker
Array of `{id, name, brand, type, flavors[], scoopGrams, perScoop: Macros, ingredientKey, note}`. type is one of whey_isolate | whey_blend | casein | whey_casein_blend | plant | egg | collagen. Also `Resources/source_powder_brands.json`: {recipeId: "brand stated by the source"}.
- A recipe has a protein powder line when a base/mixIn line's catalog category is `protein_powder`, or its key starts with `protein_powder` or is `casein_powder` or `collagen_powder`. Such recipes show a **Protein powder picker** row under the milk picker: "Your protein powder: Dymatize ISO100 ▾". The menu is grouped by type, with the note shown as a footnote of the selected item. The default comes from Settings ("My protein powder"); if none is set, the line keeps its catalog nutrition.
- Nutrition: line grams = grams ?? count × scoopGrams ?? defaultGrams. The chosen powder's nutrition is perScoop × grams / scoopGrams. The delta against the original line flows into both calorie sources, exactly like the milk delta.
- If source_powder_brands has the recipe, show "Source used: <brand>" under the picker.
- The shopping list uses the chosen powder's name.
- Settings has "My protein powder", next to "My milk".
- Custom powders: "Add my powder…" through the same Open Food Facts scan, search or manual entry flow as custom milks, using a per-scoop serving.

"course": "dinner",              // breakfast | lunch | dinner | snack | dessert | drink | side | sauce
"bookCategory": "Dinner: Kebab, Pizza",   // the book's own contents heading
"servings": 1,

"containsEgg": true,
"vegAdaptation": {               // present when vegetarian == false
  "summary": "Bacon → smoky tempeh strips (protein matched)",
  "swaps": [{"replaces": "<exact original ingredient text>", "with": Ing, "note": "Pan-fry 3 min per side"}],
  "steps": ["full instruction list for the vegetarian version"],
  "macrosPerServing": {"calories": 0, "protein": 0, "carbs": 0, "fat": 0, "sugar": null, "fiber": null}

```
Also: the catalog entries get `"vegetarian": false` plus a `vegNote` for gelatin, marshmallows, regular Jell-O gelatin, Worcestershire, fish sauce, parmesan (animal rennet), lard, chicken/beef stock and similar. Each comes with veg swaps (agar, vegan marshmallows such as Dandies, vegetarian Worcestershire, vegetarian parmesan…).

UI:
- **Segmented control**: Creami | Desserts | Meals (+ Drinks if any). Meals get a course filter (chips: Breakfast, Lunch, Dinner, Snack, Side, Sauce) and "Book" filter chips per source book.
- **Settings → "I'm vegetarian"** (default ON) and "I avoid eggs" (default OFF).
- **Veg mode ON**:
  - A recipe with a vegAdaptation shows the vegetarian version by default: replaced ingredient lines are highlighted with a green leaf callout ("Vegetarian swap: tofu instead of chicken" + note), the steps are vegAdaptation.steps, and the macros are vegAdaptation.macrosPerServing × servings, labelled "Vegetarian version (estimated)". A toggle at the top, "Vegetarian version | Original", switches between them.
  - Cards show a 🌱 badge: "Veg" when vegetarian as written, "Veg version" when adapted.
  - Any recipe (Creami/dessert too) with an ingredient whose catalog entry has vegetarian=false shows a callout on that line with vegNote and its veg swaps. The swap sheet lists veg swaps first.
  - Filters gain "Vegetarian as written", "Has veg version", and "No egg" (containsEgg false, or no catalog egg keys).
- "I avoid eggs" ON auto-enables the No-egg filter.

### Ranked vegetarian alternatives (user request: "alternative 1 is seitan, 2 is tofu etc.", widely available)
`Resources/veg_alternatives.json`:
```json
{"roles": {"chicken_strips": {"label": "Chicken (strips / crispy / shredded)",
   "matchKeys": ["chicken_breast", "chicken_thigh", "chicken_tenders", "popcorn_chicken", "..."],
   "alternatives": [
     {"key": "tofu_extra_firm", "name": "Extra-firm tofu", "availability": "everywhere",   // everywhere | most_stores | specialty
      "whereToBuy": "Walmart, Target, Kroger, Costco, Trader Joe's", "brands": "Nasoya, House Foods, Trader Joe's Organic",
      "per100g": {"calories": 145, "protein": 16, "carbs": 3, "fat": 8, "sugar": 1, "fiber": 2},
      "prep": "Press 15-20 min, cut into strips, toss in cornstarch, air-fry 200 °C / 400 °F for 12-15 min",
      "textureMatch": 3, "why": "Cheap, everywhere, crisps well"}]}},
 "keyToRole": {"chicken_breast": "chicken_strips", "...": "..."}}
```
- Each vegAdaptation swap's original line maps to a role through `keyToRole[original key]`, or a role whose matchKeys contain it, or a keyword match on the original text.
- The detail screen shows the swapped line with a horizontal picker "Alt 1 · Alt 2 · Alt 3 …". Each chip has the name, an availability badge (green Everywhere / blue Most stores / orange Specialty), and the text "+12 kcal · −3 g P" versus the default. Selecting a chip shows whereToBuy, brands, prep and why.
- Default selection: the alternative the vegAdaptation already chose (when it matches one in the role), else Alt 1. Settings has "Prefer easy-to-find alternatives" (default ON). When it's on, the default is the first alternative with availability "everywhere", unless the user picked one for that recipe. The choice persists per recipe and line.
- Amount = protein-matched against the ORIGINAL meat line: grams = originalGrams × meatProtein100 / altProtein100, rounded to 5 g. originalGrams comes from the original Ing (grams/ml/count with catalog), and meatProtein100 from the catalog entry of the original key, or the role's `meatPer100g` field.
- Nutrition: veg macros = vegAdaptation.macrosPerServing + (chosen alt nutrition − default alt nutrition)/servings. When the default sub isn't in the list, use the original macros − meat + alt instead.
- Cook mode, the shopping list and the steps show the chosen alt's name. Steps text that mentions the default substitute's name gets that name replaced with the chosen alternative, and the alt's prep line is shown as step 0.

### Guides tab (replaces nothing; 6th destination: put "Guides" inside the Settings tab's top section, or as a toolbar button on Recipes. Builder's choice, but it must be one tap from the home screen)
`Resources/guides.json`: array of `{id, title, subtitle, icon (SF Symbol), sections: [{heading, body (plain text with \n), bullets: [String]?, table: {columns: [String], rows: [[String]]}?}]}`. Rendered as clean article pages.
- **High-protein paneer guide** + **Paneer calculator**: pick a milk from base_liquids (milk / ultra_filtered families) and a volume (0.5–4 L) and get the estimated pressed paneer yield (g) and macros, total and per 100 g, using the model in `Resources/paneer_model.json`: `{proteinRecovery, fatRecovery, lactoseRecovery, moisturePct, notes}`, with optional per-milk overrides keyed by liquid id. Yield g = (milk protein g × proteinRecovery + fat g × fatRecovery + carbs g × lactoseRecovery + ash) / (1 − moisturePct). Show a comparison table across all milks for 1 L, sorted by protein per 100 kcal.
- Other guides come from guides.json (protein sources cheat sheet, seitan from vital wheat gluten, pressing tofu, soy chunks, etc.).

## Nutrition logic (Services/NutritionCalculator.swift) — the core of the app

1. **Grams of a line**: `grams` ?? `ml * gramsPerMl(1.0 default)` ?? `count * gramsPerCount` ?? `defaultGrams` ?? 0. Lines that resolve to 0 g are reported as "unknown amount" (count them; show a small note "2 ingredients not counted").
2. **Line nutrition**: `per100g * grams / 100`, using the user's nutrition override for that key if one exists (see Nutrition sources).
3. **Calculated pint** = sum over base + mixIns (skip optional lines unless the user ticked them).
4. **Base liquid**: the first `base` line whose catalog category is milk / protein_shake / plant_milk / ultra_filtered. When the user picks a different BaseLiquid:
   - liquid → liquid: same volume. Volume = line ml ?? grams / gramsPerMl ?? count * servingMl.
   - protein shake line ("1 vanilla protein shake (350-400 ml)") → shake: one serving of the chosen shake (count × perServing).
   - Nutrition of the chosen liquid = perServing × volume / servingMl.
   - delta = chosen − original line nutrition.
5. **Displayed macros** depend on the Calorie source picker (per recipe, default from Settings):
   - **Book / Source** (default): recipe.macros + Σ deltas (milk change, swaps, scaling). If recipe.macros is null, fall back to Calculated and label it "estimated".
   - **Calculated**: the calculated pint with the user's milk, swaps and overrides.
   Show which source is active, and a "Compare" sheet listing Book vs Calculated vs per-ingredient breakdown (a table: ingredient, grams, kcal, protein).
6. **Swaps** (per recipe, persisted): replacing line L with swap S: new grams = L grams × S.ratio; nutrition from S.key's catalog entry (or unchanged if null). Delta flows into both sources as in 5.
7. **Pints**: a 1–5 stepper scales all amounts and macros (batch prep). Amount text keeps the original text and appends "× 3 → 1200 g" when grams are known.
8. **Per-scoop view**: toggle "Whole pint / Per serving" with servings 1–4 (book macros are per whole pint).

### Nutrition sources (user asked: default = recipe/book numbers, but able to pull calories from other sources)
- **Recipe/Book** numbers (default).
- **Built-in database** (`ingredients.json` per-100 g values, USDA-based) → "Calculated".
- **Open Food Facts** (free, no key): barcode scan (VisionKit `DataScannerViewController`, iOS only, guarded with `#if os(iOS)` and `DataScannerViewController.isSupported`) or text search. Endpoints: `https://world.openfoodfacts.org/api/v2/product/{barcode}.json?fields=product_name,brands,nutriments,serving_size` and `https://world.openfoodfacts.org/cgi/search.pl?search_terms={q}&search_simple=1&json=1&page_size=20&fields=code,product_name,brands,nutriments`. Read `energy-kcal_100g`, `proteins_100g`, `carbohydrates_100g`, `fat_100g`, `sugars_100g`, `fiber_100g` (missing → 0). Send a `User-Agent: CreamiCravings/1.0 (personal app)` header.
- **Manual label entry**: serving size (g or ml) + calories, protein, carbs, fat, sugar, fiber → converted to per-100 g.
Results from OFF / manual can be saved as (a) an override for a catalog ingredient key, or (b) a new custom BaseLiquid ("My milk") that appears in the milk picker. Overrides show a small source badge ("OFF", "Label") on the ingredient row.

## Affiliate products, alternatives and swaps (user's explicit asks)
- An ingredient whose catalog entry has `affiliate` gets a highlighted callout under the row (tinted rounded box, `tag.fill` icon): **"Affiliate pick · Prime Bites"**, then **Buy instead:** storeAlternative and **Make it:** homemadeAlternative.
- Every ingredient row has a context menu and a trailing button "Swap / I don't have it" opening a sheet: alternatives (store + homemade), the swap list with each swap's macro impact for this recipe ("+38 kcal, −9 g protein"), and a toggle "I don't have this" (sets it missing in the pantry).
- The milk line (e.g. "400 g fat free ultra-filtered milk") ALWAYS shows its swap options too (regular skim + nonfat dry milk powder, skim + protein powder, 2% milk, etc. — from the catalog).
- Missing ingredients (pantry) are struck through with a "Swap: <first swap>" suggestion inline.

## Screens

TabView with 5 tabs: **Recipes**, **Favorites**, **Freezer**, **Shopping**, **Settings**.

1. **Recipes** (NavigationStack):
   - `.searchable` across name, ingredient text, tags, source site. Search is case- and diacritic-insensitive and token-based (every word must match somewhere).
   - Top: horizontal chip bar of quick filters (Favorites, Book, Web, Healthy, Indulgent, Sorbet, High-protein, No affiliate products, Can make now) + a "Filters" button showing the active filter count badge.
   - Sort menu: Name, Calories ↑, Protein ↓, Protein per 100 kcal ↓, Recently made, Rating.
   - Grid of cards (2 columns). Card: photo (or a generated gradient placeholder chosen from the recipe's first flavor tag with an SF Symbol, e.g. sorbet → `leaf.fill`, chocolate → brown gradient), name, kcal + protein pills, star button (top-right, haptic). Context menu: Star, Add to shopping list, Start freeze timer, Mark as made.
   - "Surprise me" toolbar button: random recipe among the current filtered results.
   - Header line: "143 recipes".
2. **Filter sheet** (all combinable; AND between groups, OR inside a group):
   - Source: Book / Web.
   - Tags (all from the vocabulary, as a flow layout of toggle chips).
   - Affiliate products: "Hide recipes with affiliate products", or exclude specific brands (list all affiliate brands found in the catalog, e.g. Prime Bites, FUUL, Hormbles Chormbles, Lakanto).
   - Base liquid: fat-free ultra-filtered milk, protein shake (any flavor, with per-flavor chips: vanilla, chocolate, caramel, strawberry…), regular milk, heavy cream, plant milk, yogurt/cottage cheese, fruit/juice (derived from the base liquid line's catalog category and key).
   - Contains / excludes ingredient (searchable picker over ingredient names).
   - Allergens to avoid (dairy, egg, gluten, peanut, tree nut, soy, coconut).
   - Max calories slider (100–1500), min protein slider (0–60 g), using the displayed macros (with the user's default milk).
   - Pantry: "Can make now" (all non-optional ingredients present), "Can make with swaps" (every missing one has a swap).
   - Favorites only, Has video, Made before.
   - Reset button. Filters persist between launches.
3. **Recipe detail**: hero photo (stretchy header), name, source line (book page / site link), star, tag chips; macro row (colored pills like the book: calories red, protein green, carbs blue, fat orange, sugar, fiber) with source picker (Book | Calculated) and an "estimated" label when relevant; **Milk picker** row ("Your milk: Fairlife 2% ▾" → grouped menu by family, plus "Add my milk…" which opens OFF scan/search/manual); pints stepper; Base and Mix-ins sections with affiliate callouts and swap buttons; Instructions (numbered); Pro tip card; "Watch video" (opens videoURL) and "Open source" (url) buttons; bottom bar: **Start cooking**, **Freeze timer**, **Add to list**; Made-it log (date, 1–5 stars, note) section.
4. **Cook mode** (full-screen cover): page 1 = ingredient checklist with scaled amounts and the active milk/swaps applied; then one step per page, large text, swipe or Next; screen stays awake (`UIApplication.shared.isIdleTimerDisabled`, iOS only) while open; last page: "Rate it" (stars + note → made log).
5. **Freezer**: pints currently freezing (recipe, started, ready-at, live countdown with `Text(timerInterval:)`, progress ring). Starting a timer schedules a local notification ("Your Americone Dream pint is ready to spin 🍦") at freezeHours (asks notification permission the first time). Swipe to delete (cancels notification). Ready pints float to top with a "Spin it" button → Cook mode starting at the step after freezing.
6. **Shopping**: items grouped by catalog category; adding a recipe adds its non-pantry-staple ingredients (with the user's milk and swaps applied), merging by key and summing grams where known; check off; swipe to delete; "Clear checked"; share as plain text (ShareLink).
7. **Settings**: My default milk (picker); default calorie source; Pantry (list of all catalog ingredients with "have" toggles, search, plus "Mark all staples as have"); Nutrition overrides (list, delete); custom milks (list, delete); about/credits (book title + author, web sources count).
8. **Favorites**: same grid as Recipes filtered to starred, with the same search.

Spotlight: index recipes with CoreSpotlight (name, tags) so they show in iPhone search; opening one deep-links into the recipe (`onContinueUserActivity(CSSearchableItemActionType)`).

## Persistence (Services/UserStore.swift)
One `@Observable final class UserStore` holding a Codable `UserData` struct saved as JSON to Application Support (debounced on change, atomic write). Fields: favorites: Set<String>, recipeMilk: [recipeId: liquidId], defaultMilkId: String?, swaps: [recipeId: [lineIndexKey: swapIndex]], pints: [recipeId: Int], calorieSource default + per-recipe, pantryMissing: Set<String> (keys the user does NOT have; everything else counts as present), nutritionOverrides: [key: Override(per100g, sourceLabel, productName)], customLiquids: [BaseLiquid], madeLog: [Entry(recipeId, date, rating, note)], freezer: [FreezeTimer(id, recipeId, start, readyAt)], shopping: [ShoppingItem], filterState: FilterState. Missing/corrupt file → start fresh (never crash).

## Visual design
- Use system components so iOS 26 Liquid Glass applies automatically (TabView, toolbars, sheets, `.glassEffect` NOT required). Accent pink; macro colors as above; SF Symbols; rounded cards with 16 pt corner radius, subtle shadows; `.contentTransition(.numericText())` on macro numbers when milk/swaps change; `.sensoryFeedback` on star/check actions; matched-geometry or `.navigationTransition(.zoom)` from card to detail (iOS 18).
- Dark mode supported. Dynamic Type friendly (no fixed heights on text).

## Constraints
- Models/ and Services/ import Foundation only (plus Observation), so they compile and run on macOS for the logic checks. iOS-only APIs (UIKit, VisionKit, `UIApplication`, `navigationBarTitleDisplayMode`, etc.) must be wrapped in `#if os(iOS)`, so the whole app also type-checks against the macOS SDK.
- No third-party packages. No hard-coded secrets. No analytics.
- Recipes JSON is loaded once at launch off the main thread; app must stay smooth with 500 recipes (precompute search haystacks and base-liquid info in RecipeStore).
